# 模板设计

2026-10-29。依据已讨论的 MultiButton 分层方案，按独立可复制模板落地。

| 职责 | 位置 | 所有者 |
|---|---|---|
| 状态识别算法 | ThirdParty/MultiButton | 固定版本后端 |
| 实例和事件桥接 | Module/mod_button | 单一静态管理器 |
| 物理 GPIO 映射 | 宿主 BSP | 板级能力所有者 |
| 周期调度、产品动作 | 宿主 App；examples 展示调度部分 | 应用运行所有者 |

没有外部芯片协议，不新增 Device/Driver。没有多消费者分发需求，不新增 Services。沿用宿主 OS 边界，不新增 OSAL。
Module 仅包含自身接口和第三方算法；第三方头不出现在公共头中。readLevel 输入是逻辑 ID -> 0/1 电平，硬件访问发生在注入适配函数中。

公共配置由初始化复制，第三方对象始终在静态数组内。后端全局链表意味着单一管理器，不能用多个包装对象假装隔离。
读取与事件回调都由 ProcessTick 同步触发；processing 标记覆盖两类回调，防止同步反入破坏遍历。
生命周期不增加任务、锁或队列。Start/Stop 幂等；启动失败撤销已触及对象；重启先重建后端状态以清除旧手势。

使用七个事件桥接函数，不直接把 get_button_event 转为公共枚举：上游 PRESS_REPEAT 调用点并不先更新 event 字段，直接查询会误报。
只按事件位置转换类型，不依赖公共枚举数值恰好与第三方相同。

App 示例将单调时间与真实采样分开，丢失的时槽仅计数，不在循环中补扫。时钟完整回绕周期内利用 uint32 差值处理回绕。
后端不接收 elapsed 参数，因此漏扫后的手势时间延后是已知限制。需要跨睡眠准确识别时应重新评估后端时间模型，不能靠修改包装计数伪装支持。

固定容量默认 16，可配置 1..256，初始化 ID 唯一性检查为 O(N²)，只在停止态执行；每次扫描 O(N) 加输入/事件回调耗时。
不承诺互斥安全、动态注册、跨任务事件队列、运行时阈值或组合键识别。

验证采用真实后端。仅为不可自然发生的注册失败设置链接接缝；通过编译期重命名后端 button_start 保留真实链表操作，测试在第二次注册前注入失败。接缝不进入产品目标。
